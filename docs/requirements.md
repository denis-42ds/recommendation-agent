# Requirements — Recommendation Agent MVP

**Дата актуализации:** 27.11.2026
**Статус:** Cross-sell MVP реализован; Docker и Cloud Run deployment подтверждены пользователем.

## 1. Назначение и scope

Целевой Recommendation Agent предназначен для личного кабинета интернет-магазина Softline.

Сценарии целевого продукта:

- Cross-sell — дополняющие товары и услуги.
- Up-sell — расширенные или более подходящие решения.
- Renewal — продление лицензий и подписок.

**DECISION:** в текущем MVP реализуется Cross-sell. Up-sell и Renewal не должны задерживать сдачу работающего MVP.

## 2. Сегменты и ограничения

- B2B и B2C обрабатываются раздельно.
- Для B2C запрещено использовать отрасль (`industry`) и корпоративный профиль клиента.
- Для B2B используются только фактически доступные и разрешённые поля.
- Не выводить отсутствующие сведения о лицензиях, совместимости, ценах или наличии.
- Co-purchase — сигнал совместной покупки, а не доказательство технической совместимости товара.

## 4. Контракт рекомендации

Каждая запись содержит:

- `product_id`;
- `recommendation_type`;
- `score`;
- `reason_codes`;
- `evidence`;
- `explanation`.

В текущей реализации `product_id` — `offer_id` из каталога.

Требования:

- `product_id` разрешается в используемом каталоге;
- `score` воспроизводим;
- `reason_codes` соответствуют сработавшим правилам;
- `evidence` содержит факты, подтверждающие объяснение;
- не генерировать вымышленные SKU, цену, наличие, срок лицензии или совместимость.

## 5. Логика Cross-sell

### Candidate Generation

1. Получить историю `item_id` клиента.
2. Найти co-purchase кандидатов в графе.
3. Агрегировать число совместных корзин и источники из истории.
4. При недостатке co-purchase позиций добавить Popularity fallback соответствующего сегмента.

### Business Filtering

- исключить уже купленные `product_group`;
- исключить кандидатов без доступного предложения в используемом каталоге;
- оставить не более одного предложения на `product_group`;
- не делать вывод о технической совместимости только по co-purchase.

### Ranking

- co-purchase имеет приоритет перед popularity fallback;
- score и tie-break детерминированы;
- выбор offer внутри `product_group` стабилен: `(offer_id, item_id)`.

### Cold-start

- без истории используется сегментная popularity;
- результат маркируется как неперсонализированный;
- не создавать вымышленные позиции при нехватке каталога.

## 6. Explainability

Допустимые основания:

- товар встречался в корзинах вместе с конкретным товаром из истории;
- товар попал в popularity fallback по Train;
- кандидат прошёл определённые бизнес-фильтры.

Запрещено:

- объявлять товар технически совместимым на основании co-purchase;
- использовать отрасль или корпоративный профиль для B2C;
- формировать утверждения, не подтверждённые evidence;
- отображать цену, если её нет в модели/источнике.

## 7. Качество и метрики

Offline-метрики проекта:

- Precision@K;
- Recall@K;
- NDCG@K;
- MAP@K;
- Coverage;
- Diversity;
- Fill Rate;
- Latency.

Для backtest действует отдельный зафиксированный протокол в `STATE.md` и ADR-003. Не менять его ради улучшения метрик.

Диагностика текущего движка:

- 19 008 клиентов обработано;
- Fill Rate 100% для ALL/B2B/B2C;
- Top-3 заполнен всем клиентам в диагностическом прогоне.

Fill Rate характеризует заполнение позиций, а не релевантность. Он не заменяет Precision@K и не доказывает бизнес-эффект.

http://localhost:8080

## 9. Данные и публичная демонстрация

Правила:

1. Не включать в репозиторий секреты, API-ключи, `.env`, пароли и учётные данные.
2. Не расширять разрешение организаторов на другие цели обработки или публикации данных без отдельного основания.
3. Проверять состав Docker-образа перед публикацией новых версий.

## 10. Не входит в scope

- Полноценные Up-sell и Renewal.
- LLM в критическом пути.
- RAG, vector DB, отдельная БД.
- FastAPI и микросервисы.
- Обучение ML-модели.
- Автоматическое обогащение каталога внешними источниками.
- Дальнейшая оптимизация Match Rate без конкретной блокирующей причины.
- Интеграция с реальным личным кабинетом Softline.
- Сбор и использование feedback по кликам/показам.
- Онлайн-эксперимент.
