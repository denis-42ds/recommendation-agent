# ADR-003: Baseline v5 и классификация попаданий по product_group

**Status:** ACCEPTED

## Контекст

В датасете v5 появилась колонка `product_group`, позволяющая различать варианты одного продукта и новые продуктовые семейства.

Организаторы уточнили:

- Основное сравнение с baseline проводится по всем 817 `item_id`, независимо от текущей доступности и наличия товара в актуальном feed.
- Для демонстрации разрешено показывать только доступные предложения.
- Попадание считается вариантом, если `product_group` рекомендованного товара уже присутствует в истории клиента.
- Иначе попадание относится к новому продукту.

## Решение

1. Использовать `docs/source-materials/Датасет_Рекомендации_ЛК_v5.xlsx` как основной входной файл baseline.
2. Сохранить существующие правила расчёта Popularity и Co-purchase.
3. Сохранить формулу Precision@3 с делителем 3.
4. Построить отображение `item_id → product_group` по всем строкам листа «Продажи».
5. Если `product_group` пуст, использовать `item_id` в качестве fallback.
6. Если один `item_id` связан с несколькими `product_group`, останавливать расчёт с ошибкой.
7. Не объединять товары в baseline или Product Graph по `product_group`.
8. Добавить дополнительную статистику успешных попаданий:
   - `variant_hits`;
   - `new_hits`;
   - `total_hits`;
   - `variant_share`.
9. Сохранять статистику в `artifacts/baseline/hit_split.csv`.

## Обоснование

`product_group` нужен для классификации результата рекомендации, но не заменяет идентификатор конкретного товара `item_id`.

Это позволяет отличать рекомендацию другой версии или редакции продукта от рекомендации нового продуктового семейства, не меняя официальный протокол Precision@3.

## Последствия

- Baseline остаётся сопоставимым с предыдущей реализацией по основным метрикам.
- Появляется дополнительная аналитика структуры успешных рекомендаций.
- Граф продолжает хранить отдельные узлы для каждого `item_id`.
- Для демонстрации применяется отдельное ограничение по текущей доступности товара.

## Критерии пересмотра

Решение пересматривается, если организаторы изменят определение `product_group`, правила подсчёта попаданий или протокол оценки.
