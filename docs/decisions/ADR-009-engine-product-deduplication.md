# ADR-009: Идентичность товара и дедупликация в Recommendation Engine

- **Статус:** ACCEPTED
- **Дата:** 27.11.2026
- **Контекст:** реализация локального Recommendation Engine

## Контекст и проблема

В исходных продажах и графе совместных покупок товары представлены через `item_id`. Для пользовательской выдачи требуется не показывать несколько вариантов одной товарной группы, исключать уже купленные группы и ссылаться на конкретное предложение каталога.

При этом нельзя менять идентичность узлов baseline и графа: это нарушило бы сопоставимость с существующим backtest и графом.

В каталоге `matched_products.json` конкретное предложение имеет `offer_id`, а исходный товар связан с `product_group`.

## Рассмотренные варианты

1. Перевести baseline и граф с `item_id` на `product_group`.
2. Сохранять `item_id` во всех контурах и не выполнять дедупликацию в выдаче.
3. Сохранить `item_id` в аналитических артефактах, но использовать `product_group` для фильтрации/дедупликации Recommendation Engine, а `offer_id` — как ID конкретного предложения в результате.

## Решение

**DECISION:** выбран вариант 3.

- Baseline и product graph продолжают работать на исходных `item_id`.
- История клиента передаётся в движок как `item_id`.
- Кандидаты из графа агрегируются для пользовательской выдачи с учётом `product_group`.
- Если `product_group` клиента уже присутствует в истории, эта группа исключается из рекомендаций.
- В итоговой выдаче допускается не более одного предложения на `product_group`.
- Для группы выбирается доступное предложение каталога детерминированно по `(offer_id, item_id)`.
- `Recommendation.product_id` содержит `offer_id`.
- Предложения без доступного сопоставления в используемом каталоге не выдаются.

## Причины

- Сохраняется совместимость baseline и графа с историческим протоколом.
- Пользователь не получает несколько вариантов одной товарной группы.
- `product_id` можно разрешить в конкретную запись каталога.
- Решение детерминировано и не требует новой инфраструктуры.

## Последствия

Положительные:
- аналитические артефакты не меняют гранулярность;
- выдача дедуплицирована на уровне `product_group`;
- продуктовая карточка ссылается на `offer_id`.

Ограничения:
- качество выдачи ограничено полнотой сопоставления каталога;
- выбор предложения внутри группы не означает техническую или коммерческую оптимальность;
- исторического snapshot доступности каталога нет;
- `offer_id` не следует интерпретировать как `item_id`.

## Критерии пересмотра

Пересмотреть решение, если:
- бизнес-владелец задаст другую формальную модель продуктовой идентичности;
- появится авторитетный master-data mapping;
- потребуется выдавать несколько вариантов одной группы с явным UX-сценарием;
- появятся исторические snapshots каталога и наличия.

## Связанные решения

- ADR-002 — Product Graph остаётся на уровне `item_id`.
- ADR-003 — baseline v5 и `product_group` в hit-split.
- ADR-008 — Cross-sell first и scope freeze.
