# Recommendation Agent

MVP рекомендательной системы для личного кабинета интернет-магазина Softline.

## Цель MVP

Показать полный демонстрационный цикл: выбор клиента → получение контекста → генерация Top-3 рекомендаций → объяснение на основе фактов → отображение результата в веб-интерфейсе.

Поддерживаемые бизнес-сценарии целевого продукта:
- **Cross-sell** — дополняющие товары и услуги.
- **Up-sell** — расширенные или более подходящие решения.
- **Renewal** — продление лицензий и подписок.

**Приоритет текущего MVP: Cross-sell.** Up-sell и Renewal не должны задерживать готовность основного сценария.

LLM не требуется для базовой функциональности. Объяснения формируются детерминированно на основе фактов и `reason_codes`.

## Локальный запуск

Клонирование репозитория и переход в его каталог:

```bash
git clone git@github.com:denis-42ds/recommendation-agent.git
cd recommendation-agent
```

Создание виртуального окружения:

```bash
python3 -m venv .venv
```

Активация окружения:

Linux/macOS:

```bash
source .venv/bin/activate
```

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Установка зависимостей:

```bash
python -m pip install -e ".[dev]"
```

Запуск:

```bash
streamlit run app.py
```

## Архитектура

```text
Streamlit UI
    |
    v
Recommendation Engine
    |
    +--> Candidate Generation
    +--> Business Filtering
    +--> Ranking / Scoring
    +--> Explanation
    |
    v
Top-3 recommendations
```

Для MVP используется модульный монолит: один процесс Python и одно приложение. Отдельные микросервисы, FastAPI, vector DB и RAG не требуются.

## Данные и ограничения

- Реальный датасет используется для локального анализа и backtest.
- Не публиковать исходный датасет, клиентские данные и персональные сведения.
- Для публичной демонстрации использовать синтетические или обезличенные демонстрационные данные.
- В B2C запрещено использовать отрасль и корпоративный профиль клиента.
- Товар в рекомендации должен существовать в доступном каталоге; нельзя придумывать SKU, цену, наличие или совместимость.
- Граф отражает совместные покупки, а не доказанную техническую совместимость.
